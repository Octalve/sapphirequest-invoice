# Phase 2 Manifest

## Base checkpoint

Phase 2 was implemented directly on the verified Phase 1 repository. The Phase 1 source and documentation were not recreated from scratch.

- Sapphire Quest visual identity and supplied logo/icon assets.

- Add/remove invoice rows.
- Auto-growing service/description textareas.
- Discount/tax calculation and constraints.
- Persistent bank/payment details.
- Optional notes/payment section.
- New Invoice confirmation modal.
- Meaningful PDF/PNG filenames.
- Renderer/export/domain separation.

## Implemented in Phase 2

### Paper support

- Added `PaperSize` type: A4, A5, LETTER.
- Added explicit physical paper dimensions.
- Added paper selection to the toolbar.
- Persisted paper choice in draft version 4 and dedicated preference storage.
- Added migration fallback for Phase 1 `v3` and standalone `v2` drafts.
- Browser preview now reflects selected paper proportions.

### A5 composition

- A5 uses a dedicated compact composition.
- Header/logo/title proportions are reduced intentionally.
- Contact/client metadata spacing is tightened.
- Table typography/padding is adapted.
- Payment/notes, totals and footer receive A5-specific sizing.
- A5 safe margins are smaller than A4 while remaining explicit.

### Export density

- A5 defaults to compact document density.
- A4/Letter use normal density.
- A modest A4/Letter overflow can switch to export-only compact density before a second page is created.

### PDF efficiency

Removed the legacy PDF behavior of:

- fixed A4 output;
- 3x capture;
- lossless PNG pages;
- blind fixed-height slicing.

New behavior:

- 2x PDF capture;
- JPEG page encoding at controlled quality;
- Blob/Uint8Array image flow rather than large PNG data URLs;
- jsPDF compression enabled;
- A4/A5/Letter page dimensions selected dynamically;
- one-page fit tolerance for very small overflow;
- PDF metadata set.

### Pagination

- Added pure `planPageSlices` helper.
- Rows expose semantic safe-break markers.
- Extra-details and closing/totals areas expose keep-together boundaries.
- Genuine multi-page output chooses the latest safe boundary before the page edge where possible.
- A hard cut occurs only when no safe break exists in the usable region (for example one pathologically tall item).
- Continuation pages receive invoice context.
- Continuation pages that begin inside the item table receive a compact table heading.
- No zero-height/blank trailing page is generated by the planner.

### Footer/totals

- Totals and the final footer are grouped into the document closing block.
- A safe break is exposed before that closing block so it moves as a unit when space is insufficient.
- Footer negative spacing is now tied to the selected page's explicit internal margin rather than hard-coded `-mx-10/-mb-10` values.

### Verification fixtures

Added tests for:

- A4 short invoice;
- A5 short invoice;
- long descriptions;
- many rows;
- totals near the page boundary;
- genuine multi-page fallback;
- exact capacity/no blank trailing page.

## Intentionally not introduced

- Neon/PostgreSQL;
- Prisma;
- server authentication;
- RBAC;
- database invoice history;
- shared multi-user numbering;
- commercial dashboard pages;
- server-side commercial PDF renderer.

Those belong to the separate Octalve Invoice product defined in the PRD.
